# DASTIN — نسخهٔ سه‌سکشنی، استاتیک و آمادهٔ انتشار

این پروژه بدون فریم‌ورک، npm، build یا بک‌اند اجرا می‌شود. تمام مسیرها نسبی‌اند؛ بنابراین هم روی **Cloudflare Pages** و هم زیرمسیر **GitHub Pages** کار می‌کنند.

## معماری صفحه

سایت عمداً فقط سه بخش اصلی دارد:

1. **دستین** — معرفی برند، فضای آشپزخانه، نمونه‌های منتخب و روایت خانگی/لوکس.
2. **کاتالوگ زنده** — همهٔ محصولاتی که ادمین مدیریت می‌کند؛ فیلتر، lazy loading و modal جزئیات دارد.
3. **ارتباط** — اینستاگرام، واتساپ، تلگرام و ایمیل؛ متن و لینک همه از پنل قابل تغییر است.

اینتروی تمام‌صفحه، هدر و modal محصول، بخش مستقل محسوب نمی‌شوند.

## پنل خصوصی

مسیر پنل در منوی سایت لینک نشده و برای موتور جست‌وجو `noindex` است:

```text
https://YOUR-DOMAIN/studio-dastin/
```

رمز اولیه: `Dastin!1405`

پیش از انتشار، در `studio-dastin/admin.js` مقدار `PASSWORD_HASH` را تغییر دهید:

```bash
printf 'YOUR-NEW-PASSWORD' | sha256sum
```

> رمز و مسیر مخفیِ سمت کاربر، امنیت واقعی نیستند. برای امنیت عملی روی Cloudflare، مسیر `/studio-dastin/*` را با **Cloudflare Access** محافظت کنید.

### مدیریت محتوا

در Studio می‌توان:

- محصول را با تصویر، نام، دسته‌بندی، **قیمت، وزن، کپی‌رایت و توضیح** افزود یا ویرایش کرد.
- تصویر را حذف، جایگزین و ترتیب محصول را جابه‌جا کرد.
- تصویرهای تازه را به WebP (حداکثر ضلع ۱۸۰۰px) فشرده کرد.
- اطلاعات ارتباطی Instagram / WhatsApp / Telegram / Email را عوض کرد.
- پشتیبان کامل JSON گرفت یا بازیابی کرد.

## انتشار تغییرهای ادمین با GitHub

چون سایت static است، مرورگر نمی‌تواند خودکار در repository شما commit کند. راه استاندارد و بدون بک‌اند اختصاصی این پروژه:

1. در پنل، دکمهٔ **«خروجی GitHub»** را بزنید.
2. فایل `catalogue.json` دانلودشده را در ریشهٔ پروژه جایگزین کنید.
3. اگر تصویر تازه آپلود شده، فایل‌های WebP دانلودشده را داخل `assets/uploads/` قرار دهید.
4. این فایل‌ها را commit و push کنید.
5. GitHub Pages یا Cloudflare Pages خودکار نسخهٔ عمومی تازه را deploy می‌کند.

سایت عمومی در هر بار بارگذاری `catalogue.json` را می‌خواند؛ در نتیجه تغییرهای commit‌شده برای تمام بازدیدکنندگان نمایش داده می‌شوند. در همان مرورگر ادمین، تغییرهای ذخیره‌شده در IndexedDB برای پیش‌نمایش فوری اولویت دارند.

## دیپلوی در Cloudflare Pages

1. محتویات این پوشه را در یک Git repository push کنید.
2. **Workers & Pages → Create application → Pages → Connect to Git**.
3. تنظیمات:
   - **Framework preset:** `None`
   - **Build command:** خالی یا `exit 0`
   - **Build output directory:** `.`
   - **Root directory:** خالی؛ یا `dastin` اگر پروژه داخل پوشهٔ `dastin` در repo والد است.
4. Deploy کنید.

فایل `_headers` برای Cloudflare کش طولانی assetها و کش کوتاه‌تر فایل‌های HTML/JS را تنظیم کرده است.

## دیپلوی در GitHub Pages

1. این پوشه را در ریشهٔ repository قرار داده و به `main` push کنید.
2. در **Settings → Pages**، گزینهٔ **Deploy from a branch** را انتخاب کنید.
3. Branch: `main` و Folder: `/(root)`.
4. Save کنید.

## عملکرد

- گالری عمومی در batchهای ۸تایی با `IntersectionObserver` رندر می‌شود؛ بنابراین صدها محصول باعث DOM سنگین اولیه نمی‌شوند.
- تصویرها lazy load هستند؛ Blob آپلودشده فقط هنگام نیاز URL دریافت می‌کند.
- انیمیشن‌ها فقط با `transform` و `opacity` اجرا می‌شوند و حالت `prefers-reduced-motion` رعایت شده است.
- فونت Vazirmatn با `font-display: swap` از Google Fonts بارگیری می‌شود.
